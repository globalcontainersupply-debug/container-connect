# Container Connect

# GLOBAL CONTAINER SUPPLY — WORLD-CLASS SHIPPING CONTAINER SALES WEBSITE

Build a complete, production-quality, SEO-standard website for a global shipping container sales company called:

**Company Name:** Global Container Supply
**Domain:** globalcontainersupply.com
**Email:** [info@globalcontainersupply.com](mailto:info@globalcontainersupply.com)

The company supplies shipping containers to customers worldwide.

This is NOT just a landing page. Build a complete business website with a professional storefront/catalog, product detail pages, shopping cart, enquiry/checkout system, reviews, company information, media/video sections, and a secure administrative dashboard for managing the website.

Do not focus this instruction on a specific programming language, framework, database, hosting provider, or technology stack. Choose the most appropriate architecture and tools yourself based on the requirements below.

---

# 1. PRIMARY OBJECTIVE

Create a premium, trustworthy, modern international shipping-container sales website that gives the impression of an established global container supplier.

The website should make it easy for visitors to:

* Understand what Global Container Supply does
* Browse available shipping containers
* Search and filter products
* View detailed container specifications
* View multiple product images
* Watch product/company videos
* Add containers to a cart
* Review their selected containers
* Submit an enquiry/order request
* Contact the company
* Learn about shipping and worldwide delivery
* Read customer reviews
* Learn about different container types and sizes
* Understand the purchasing process
* Trust the company before making an enquiry

The overall experience should feel comparable to a premium international logistics, industrial equipment, or container trading company.

# 74. IMPORTANT IMPLEMENTATION PRINCIPLE

Do not build this as a static mockup.

Build the actual functional website.

The public website and admin dashboard must be connected so that changes made in the admin panel are reflected on the public website.

For example:

When an administrator creates a product:

1. Product is saved.
2. Product appears in the product catalog.
3. Product receives a product detail page.
4. Product can be searched.
5. Product can be filtered.
6. Product can be featured.
7. Product can be added to the cart.
8. Product appears in checkout/enquiry.
9. Product metadata is available for SEO.
10. Product can appear in related/featured sections.

When an administrator uploads a video:

1. Video is saved.
2. Admin can mark it as featured.
3. Featured video appears in the appropriate homepage/video section.
4. Admin can replace or remove it.

When an administrator adds a review:

1. Review is saved.
2. If published, it appears on the Reviews page.
3. It can appear in homepage testimonial sections.
4. Admin can later edit/unpublish/delete it.

The same principle should apply throughout the entire CMS.
